# AD-popup-closer 缺陷修复与本地测试报告

本次修改针对 Windows 桌面广告弹窗的自动点击、检测框去重和检测线程启停。基线为提交 `6953abb`。

## 改动与验证

| 改动 | 原因 | 回归结果 |
| --- | --- | --- |
| 两阶段模式下，候选按钮须位于已识别的广告区域内才允许点击。见 [app.py](../app.py) | 广告标识漏检时，旧逻辑仍会放行候选按钮，普通窗口的关闭按钮有可能被误点。 | 无广告标识时无点击记录，广告区域内存在候选按钮时有点击记录。 |
| 将传给 OpenCV `NMSBoxes` 的坐标改为 `[x, y, w, h]`。见 [detector.py](../detector.py) | 旧逻辑把右下角坐标当作宽高，可能错误合并相邻目标。 | 两个相邻框均保留，两个高度重叠的框去重后保留一个。 |
| 为每次运行创建独立停止信号，在每次点击前检查信号，并在旧线程退出前拒绝再次启动。见 [app.py](../app.py) | 停止后立即启动时，旧线程可能读取到恢复的运行状态，与新线程并行。 | 模拟在推理期间发出停止请求，未记录点击。旧线程退出前启动接口返回 HTTP 409，退出后可重新启动。 |

## Windows 试跑

使用 Python 3.10 独立环境，验证了首页、截图预览和检测启停。旧版 pip 在本机默认以 GBK 读取依赖清单，使用 `python -X utf8 -m pip install -r requirements.txt` 后安装成功。

- 原版在 3200 × 2000 的全屏画面上首轮返回 3 个候选，广告标识计数为 0。
- 临时裁切到模拟弹窗后，连续多轮各返回 3 个 OCR 广告文字框、2 个关闭图标模板候选和 1 个 OCR 动作候选。裁切仅用于诊断，未并入本次改动。

## 验证范围

回归测试使用模拟检测框与点击记录，未操作真实鼠标。仓库未附 YOLO 权重，本次未验证 YOLO、真实广告关闭成功率或实际误触率。
